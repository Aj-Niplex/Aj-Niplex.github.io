ThreadForge-MCP

Multi-model chat threads over MCP — persistent, compressed, GitHub-backed

What It Is

ThreadForge-MCP is a multi-model conversational chatbot MCP server. Most MCP servers expose data or actions; ThreadForge exposes conversation itself: any MCP-capable agent — Claude, Grok, Mistral, Gemini — can open a thread, chat across turns, switch models mid-thread, and save artifacts that other agents can pick up later.

The entire server is one disciplined file: server.py, 19.6KB of FastMCP. No database, no vector store — durable state lives in GitHub itself, which means threads survive restarts, are human-readable, and cost nothing to host.

The Model Pool — routing with a reason

ModelRoleWhy
gemini-2.5-flashReliability anchorThe most reliable model in the pool — the fallback that always answers
gemini-3.8-flashPreferredBest quality per token, but can time out — falls back to the anchor
gemini-3.1-pro-previewHeavy tasksReserved for harder jobs where the flash models are not enough
gemini-2.5-flashCompression (CHEAP_COMPRESS_MODEL)Summarizes old history cheaply before it is dropped

This is not a random model list — it is a routing table with measured trade-offs: speed vs quality vs availability, encoded per model.

Context Compression

Long threads stay cheap through a best-effort compression pass:

  • Threads are capped at 30 messages
  • The latest 12 messages are always kept verbatim
  • Older messages are summarized into a thread summary by the cheap compress model — best-effort, so a failure never loses chat

Storage — threads live in GitHub

storage.txt
save-data repo (raw GitHub API)
  Chatbot MCP data/{thread_id}/
        ├── metadata.json      thread config + model prefs
        ├── messages.json      full message history
        ├── conversation.md   human-readable transcript
        ├── summary.md         compressed older history
        └── artifacts/         files shared across agents

Every thread is a folder of plain files. If ThreadForge disappeared tomorrow, every conversation would still be readable in a text editor — that is the point.

The 9 Tools

ToolWhat it does
chatSend a message into a thread, get a model reply
list_threadsEnumerate existing threads
get_threadLoad a thread's full state
save_artifactStore a file in the thread's artifact folder
list_artifactsSee what artifacts a thread holds
get_artifactRead an artifact back
update_artifactRevise an existing artifact
delete_artifactRemove an artifact
set_model_preferenceChange the model routing for a thread

Proxied Through NiPlex-MCP

Agents that already connect to NiPlex-MCP get ThreadForge for free: all 9 tools are proxied under the tf_* prefix. One connection, two servers.

Quick Start

start.txt
git clone https://github.com/Aj-Niplex/ThreadForge-MCP
cd ThreadForge-MCP
uv sync            # deps via uv
uv run server.py   # FastMCP server up

# then connect any MCP client:
# tools: chat, list_threads, get_thread,
#        save_artifact, list_artifacts, get_artifact,
#        update_artifact, delete_artifact, set_model_preference
