NiPlex-MCP

73 active tools, one MCP connection — the production toolkit under the ecosystem

What It Is

NiPlex-MCP is a production Model Context Protocol server that gives any connected agent the owner's full toolkit: GitHub operations, cloud sandboxes, HidenCloud file operations, web and YouTube search, Gemini analysis — all behind one authenticated MCP connection. It runs as a FastMCP service on port 7860 and auto-deploys on every push to main, so the server on Horizon is always the latest committed code.

It is deliberately boring in the best way: security-reviewed, allow-listed dispatch, and organized as 10 manager classes under tools/managers/ — one per domain — instead of one giant flat file.

Staged for the Future — 14 Hidden Tools

Besides the active 73, 14 tools are implemented but hidden, staged behind future proxy MCP servers rather than exposed now:

  • E2B sandbox — 3 tools (a third sandbox provider, waiting in reserve)
  • Neural — 2 tools (ask_neural / log_to_neural — currently served through the dedicated Neural-MCP; see the Neural stack)
  • Google Workspace — 9 tools (Gmail draft, Calendar, Drive, Docs — implemented but not yet routed publicly)

Nothing hidden is dead code — it is deliberately parked until each domain gets its own proxy, keeping the live surface exactly as large as it needs to be.

Security Posture

  • Fail-secure auth. APIKeyMiddleware guards every call — if MCP_API_KEY is not configured, the whole server answers 503 rather than running open.
  • Allow-list dispatch. Tools are dispatched through an explicit allow-list; unknown calls do not reach implementation code.
  • Security-reviewed. Audited as part of the ecosystem's security pass: no email-send, no auto-merge, no destructive default.
  • Manager isolation. Each domain lives in its own manager class, so one tool group's logic cannot leak into another.

The ThreadForge Proxy Story

ThreadForge-MCP is a separate public MCP server for multi-model chat threads. Rather than forcing agents to hold two connections, NiPlex-MCP proxies all 12 ThreadForge tools under the tf_* prefix. One connection, two servers, zero extra auth for the agent.
