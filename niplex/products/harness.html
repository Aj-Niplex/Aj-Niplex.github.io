NiPlex-Harness

The phone-first AI agent harness — Discord or Telegram is the control panel

What It Is

NiPlex-Harness is a personal AI agent harness controlled entirely from Discord or Telegram. It exists because of one hard constraint: run a real agent without a PC — the phone is the control panel. It targets free hosts like HidenCloud, so the whole system costs nothing to keep online.

Every session starts in chat. The agent runs a bounded tool loop — up to 8 tool rounds per turn — with conversation history kept on a leash (soft limit 40 messages, target 32) so long chats stay fast and cheap. Identity comes from a soul.md file: the harness knows who it is before it knows what to do. Risky actions pause and wait for approval buttons in chat. Durable knowledge lands in vault/, an Obsidian-ready Markdown store that stays human-readable — and the agent is hard-ruled never to operate on the repo root.

Configuration is conversational too: the /setup wizard walks through provider, API key and model selection pulled live from the provider API. No config files to hand-edit, no laptop needed.

Tool Categories — the real 10, from capabilities.py

The agent can reach a bounded set of tool categories. Anything not on the list simply does not exist for it. On top of these, 5 meta-tools are always on: who_am_i, report_status, get_progress, list_tool_categories, set_tool_category.

Providers

Built-in defaults out of the box: Agnes (agnes-2.0-flash), Gemini (2.0-flash) and OpenAI (gpt-4o-mini). Anthropic, OpenRouter and fully custom providers plug in through /setup — model lists are fetched live, so new models appear without code changes.

Sandbox

  • Builtin venv sandbox — 60-second cap, 512MB memory, isolated from the host.
  • auto_approve_low = true — trivially safe runs go straight through; anything risky pauses for an approval button.
  • Remote sandbox option — heavy runs can be delegated instead of running on the free host.

Security Model

Security is a stack of dedicated modules, not an afterthought: approvals, content_guard, privacy, scanner, and vault rules.

  • Allow-list only. Only allow-listed user IDs can talk to the agent at all — anyone else is ignored.
  • Approval buttons. Risky sandbox actions do not run until a human taps Approve in Discord or Telegram.
  • Sandboxed code. Untrusted Python runs isolated with hard time and memory caps.
  • File discipline. The agent never touches the repo root; durable writes go to vault/ only.
  • Public / private split. The public repo carries docs and cleaned source ready for users; experiments, agent notes and private data stay only in the private dev repo.

5-Minute Start

local.txt
# 1. Create a Discord or Telegram bot token
# 2. Configure
cp .env.example .env        # set token + your user id

# 3. Install and launch
pip install -r requirements.txt
python launch.py            # auto-installs deps via hash marker

# 4. In chat
/setup    # provider → API key → models (live list)
/help
free-host.txt (HidenCloud)
1. Upload the repo
2. Set .env values in the panel
3. Start command: python launch.py
4. /setup in Discord or Telegram — done

Full guides live in the repo: docs/SETUP.md and docs/HELP.md. Commands: /setup, /help, /reset.

Where It Sits in NiPlex

Harness is the flagship front door of the ecosystem: the loop, sandbox, approvals, memory and vault. When it needs more reach than its local tools — GitHub, cloud sandboxes, YouTube — it connects to NiPlex-MCP, the 73-tool MCP server that sits underneath everything.
